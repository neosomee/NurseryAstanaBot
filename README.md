# Телеграм‑бот для приюта животных Астаны

Телеграм‑бот помогает приютам для собак и кошек консультировать посетителей и принимать ежедневные отчеты от новых хозяев животных.

## Основной функционал

### Этап 0. Определение запроса

Стартовая точка общения пользователя с ботом.

- Приветствие нового пользователя, краткий рассказ о боте и его назначении.
- Выбор запроса через меню:
    - узнать информацию о приюте (этап 1);
    - как взять животное из приюта (этап 2);
    - прислать отчет о питомце (этап 3);
    - позвать волонтера.
- Если ни один из вариантов не подходит, бот предлагает вызвать волонтера.
- Для пользователя, который уже обращался к боту, новое общение начинается с выбора приюта, о котором нужна информация.

**Технические требования:**

- Взаимодействие только через меню бота.
- Вызов волонтера реализуется одним из вариантов:
    - по номеру телефона;
    - по никнейму в Telegram;
    - через самого бота (волонтеры регистрируются как администраторы, их чат связан с ботом).

### Этап 1. Консультация с новым пользователем

Бот выдает базовую информацию о приюте и правилах нахождения на его территории.

Функции:

- Приветствие пользователя.
- Информация о приюте: описание, особенности.
- Расписание работы приюта, адрес и схема проезда (картинка).
- Контакты охраны для оформления пропуска на машину.
- Общие рекомендации по технике безопасности на территории приюта.
- Прием и сохранение контактных данных пользователя для связи.
- Возможность переключиться на общение с волонтером, если бот не может ответить.

**Технические требования:**

- Взаимодействие через меню.
- Для схемы проезда используется изображение.
- Контактные данные валидируются по маске `+7-9**---*` (маска российского мобильного номера).

### Этап 2. Консультация с потенциальным хозяином

Бот помогает потенциальному усыновителю подготовиться к взятию животного из приюта.

Функции:

- Приветствие пользователя.
- Вывод списка животных для усыновления.
- Правила знакомства с животным до передачи.
- Список документов, необходимых для усыновления.
- Рекомендации по транспортировке животного.
- Рекомендации по обустройству дома:
    - для щенка;
    - для взрослого животного;
    - для животного с ограниченными возможностями (зрение, передвижение и т.д.).
- Советы кинолога по первичному общению с собакой.
- Рекомендации по проверенным кинологам для дальнейшей работы.
- Список возможных причин отказа в выдаче животного.
- Прием и сохранение контактных данных для связи.
- Возможность вызвать волонтера.

**Технические требования:**

- Создать базу данных для хранения:
    - информации о клиентах;
    - информации о приютах;
    - списка животных;
    - данных об усыновлениях.
- Рекомендации и справочную информацию также можно хранить в базе данных.

### Этап 3. Усыновление питомца и отчеты

После усыновления новый хозяин обязан ежедневно в течение месяца отправлять отчет о питомце.

Отчет включает:

- фото животного;
- рацион животного;
- общее самочувствие и привыкание к новому месту;
- изменения в поведении (отказ от старых привычек, появление новых).

Поведение бота:

- Принимает ежедневный отчет через меню.
- Если отправлено только фото — запрашивает текстовую часть отчета.
- Если отправлен только текст — запрашивает фото.
- Контролирует ежедневную отправку отчетов:
    - при отсутствии отчета напоминает пользователю;
    - если нет отчета более 2 дней, отправляет запрос волонтеру связаться с усыновителем.
- Позволяет волонтеру отправить стандартное предупреждение:
  > «Дорогой усыновитель, мы заметили, что ты заполняешь отчет не так подробно, как необходимо. Пожалуйста, подойди ответственнее к этому занятию. В противном случае волонтеры приюта будут обязаны самолично проверять условия содержания животного».
- В конце испытательного срока (30 дней) бот уведомляет усыновителя о решении приюта:
    - испытательный срок пройден — бот отправляет поздравление;
    - испытательный срок продлен (на 14 или 30 дней) — бот сообщает о продлении и сроке;
    - испытательный срок не пройден — бот уведомляет и дает инструкции по дальнейшим действиям.

**Технические требования:**

- Сдача отчета происходит только через меню.
- Содержимое отчета хранится:
    - в базе данных и/или
    - в файловой директории (например, для фото).
- Реализовать REST API для:
    - получения списка необработанных отчетов;
    - отметки, что отчет просмотрен;
    - выгрузки отчета по идентификатору;
    - отправки сообщения о ненадлежащем отчете.

## Архитектура и стек

- Язык: Java
- Фреймворк: Spring Boot
- БД: PostgreSQL (или другая реляционная БД)
- ORM: Hibernate
- Миграции: Liquibase
- Взаимодействие с Telegram: Telegram Bot API
- REST API: Spring Web (REST‑контроллеры)
- Тестирование: JUnit, Mockito, MockMvc (или TestRestTemplate)

## Структура проекта (план)

- `bot` — обработка апдейтов Telegram, команды, меню.
- `service` — бизнес‑логика (работа с приютами, животными, отчетами, уведомлениями).
- `repository` — доступ к базе данных.
- `controller` — REST API для работы с отчетами и админского интерфейса.
- `entity` / `model` — сущности базы данных.

1. Склонировать репозиторий.

3. Запустить миграции БД.
